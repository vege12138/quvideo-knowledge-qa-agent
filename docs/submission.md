## 1. 业务目标与范围

帮助员工查询公司制度和产品规则。输入为问题及可选对话历史，输出包含回答、状态、文档ID、片段ID、引用原文、资料缺口和执行记录。知识库包含8份合成文档、32个片段，保留日期和适用范围；不访问外网补齐公司规则。

重点处理三个业务风险：同范围制度冲突时不能随意选择一份；资料不支持时不能猜答案；工具失败时不能把未查证当作不存在资料或已回答。

## 2. 技术选择及取舍

| 选择 | 原因与代价 |
|---|---|
| Python 3.10.15 | 便于数据处理、类型校验及测试；依赖锁定见requirements.txt |
| LangGraph | 用状态图管理模型/工具循环和终止边界；下一步查询与阅读仍由模型决定 |
| DeepSeek deepseek-flash | 已验证工具调用、观察结果后继续决策；使用适配层便于替换，网络与模型仍会波动 |
| 字符n-gram TF-IDF | 小型中文知识库可本地运行、可解释、不额外依赖嵌入服务；陌生表达召回仍有限 |
| Pydantic | 校验工具参数和统一输出结构；结构正确不等于语义正确 |
| argparse / FastAPI | CLI和网页复用同一QAService，避免两套业务规则 |

框架用于工程组织，效果以实际工具行为、引用与评估记录证明。

## 3. Agent如何作决策

执行循环为：模型选择工具与参数 → 执行search_documents或read_document → 工具结果加入本轮状态 → 模型决定补查、改写查询、回答、澄清或停止。搜索只给候选与摘要，最终引用必须来自本轮实际读取的原文。

真实动态记录：[F02](../examples/evaluation/followup-20261101-r2/regression/F02.json)中，step4读取整份D07发生异常；下一次模型动作改为读取D07-C01/C02，step6成功后回答企业API申请主体。故障注入配置仅由工具包装器使用，没有告诉模型应如何重试。

默认最多8次模型调用、12次工具调用，模型请求45秒、整次运行180秒。修正和重试消耗同一预算。搜索连续失败统一计数，读取按doc_id计数；第三次故障记录后返回tool_error，同批后续调用停止。先耗尽总预算则返回incomplete。

## 4. 引用、冲突与上下文

引用校验文档ID、片段ID、原文子串和本轮读取来源。冲突澄清必须有两个不同片段；缺少套餐等上下文可追问，但必须说明缺什么。answered不能带未解决gaps，违规结果交回模型修正。字符串校验无法证明所有结论被引用支持，因此评估另外逐题核查。

同适用范围、同一事项冲突时列出双方规定并请求权威确认；日期更新不自动意味着覆盖。不同套餐的人数不同不是冲突。历史用于解析“那专业版呢”，本轮仍重新读取证据，各会话独立。

C03修复针对通用范围：只问预扣额时答20积分，不附带未问的退款争议；问退款时间时才说明60分钟内与满24小时后的冲突。采用非评估领域正反示例与结构约束，没有按题号硬编码。

当前57项确定性测试通过。真实模型开发12题、回归12题、变更4题：结构检查28/28，AI辅助语义复核28/28，用户确认待完成。自动结构检查与语义复核分开，复核绑定case_id、run_id及SHA-256。原保留题已参与修复，不能称独立测试准确率100%。

四项变更都用独立副本重建索引、清空历史：报销30改45仍与15冲突；删另一报销制度后答30；标准版5改8后答8；删除退款冲突文档后答60分钟。原知识库未改。实际记录见[变更复核](../examples/evaluation/followup-20261101-r2/mutation/review.json)。

网页另完成14项实际Edge检查及截图复核，覆盖等待、防重复、引用、多轮、新会话、错误提示和恢复。详情及历史失败见[评估报告](03-evaluation.md)。

## 7. 失败、改进与限制

初期仅通过状态/引用字符串检查，未发现附加结论与引用不完整。C03曾把退款冲突扩展成预扣金额澄清；只补answered/gaps检查仍不足，因为模型可能直接误选conflict。随后增加通用范围对照示例，并用三种问法、真正退款问题及实际网页验证。首次网页失败和K02漏引原件全部保留，没有覆盖失败或抽取好答案拼成报告。

当前硬边界保证可追踪、有限执行；不能保证随机模型每次回答都正确。资料小且合成，回归已参与开发，AI辅助复核可能遗漏。未实现生产鉴权、持久会话、上传或远程部署；这些不是本次考核的必需项。
