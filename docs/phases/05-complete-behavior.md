# 阶段 5：上下文与异常处理

状态：已形成可查收记录，实际通过与未完成项见最终结果。关联需求：R03、R04、R06—R08。

## 输入输出

输入为问题、可选历史和测试侧故障配置；故障配置不能进入模型上下文。输出为 QAResult，包含澄清原因、引用、资料缺口、错误原因、Trace 和计数。每轮重新取证，不同会话独立。

## 已批准任务

1. 保留 chat、清空会话、口语改写、故障观察与模型自主恢复。
2. search 全部 query 共用失败计数；read 按 doc_id 计数，换 chunk 或其他文档成功不清零。timeout 与 tool_exception 合计，同键成功清零；invalid_request 不计连续故障但计总工具预算。
3. 第三次失败写 Trace 和调用数后立即 tool_error，reason_code=tool_failure_limit，跳过同批剩余工具。此前模型自行选择动作。8 次模型、12 次工具和超时仍有效，先满足哪个条件就按哪个结束。
4. 新增 clarification_reason，默认 null 兼容旧 JSON；新的 clarification_required 必须为 conflict 或 missing_context，其他状态必须 null。
5. conflict 至少含两个不同的 doc/chunk 对，可来自同文档；仍须本轮读取和精确原文匹配。missing_context 允许零引用但 gaps 须明确待补充的信息。校验失败反馈模型，修正计入同一预算。
6. v1.3：回答和状态只针对当前所问属性。其他事项的冲突若不影响结论，不扩展到最终回答或改变状态；所问属性的真实冲突仍查证并澄清。
7. v1.4：原文明示、元信息与阅读后缺失的信息分开表述；操作/位置/对象关系逐项取证，不将分散事实拼成未记载的操作，不附加无必要建议。
