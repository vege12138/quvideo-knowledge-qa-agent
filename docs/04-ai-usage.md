# AI 使用记录

本项目使用 Codex 协助规划、实现、测试执行、缺陷分析和文档整理。真实业务问答使用配置的 DeepSeek 模型；Mock 仅验证程序流程。运行结果来自实际命令和模型请求，未执行项目不写为通过。

## 使用范围与责任区分

| 环节 | AI 辅助内容 | 可核实的个人参与 |
|---|---|---|
| 需求与计划 | 整理考核要求、轻量 SDD 七阶段方案、验收编号 | 用户选择企业知识问答、提供资料路径，要求 CLI 优先、阶段 4 MVP、再做网页 |
| 工程实现 | Python 包、检索/读取、LangGraph 循环、模型接入、引用校验、CLI、网页、测试及评估脚本 | 用户指定方向和阶段边界，在 MVP 后要求暂停查收 |
| 缺陷修复 | 分析故障注入、来源归属、失败边界、澄清结构及证据追踪，按批准计划修改 | 用户批准收尾计划和本地交付范围 |
| 验证与文档 | AI 执行测试、保存 Trace、逐题辅助复核、整理报告和复现步骤 | 用户亲自运行过标准版成员上限 CLI，并在对话中提供实际输出 |
| 最终验收 | AI 汇总证据及未完成项 | 完整个人复核、个人修改及最终确认尚无可核实记录，待本人补充 |

这里没有把 AI 写的代码当成候选人独立手写，也没有把 AI 执行测试说成候选人亲自运行。除已提供的 CLI 输出外，不代填个人修改、测试经历或熟练程度。

## 模型分工与复核

DeepSeek 在应用运行时选择搜索、读取、补查、回答或追问，输入为问题、历史和本轮工具观察。评估标签与参考答案不进入该 Agent 上下文。

Codex 在开发过程中可以读取评估标签、参考原文与实际输出，进行离线分析。原保留测试参与修复后，后续结果应称回归，不能再称独立保留成绩。语义复核由开发辅助 AI 逐题完成，不增加额外评审模型，不宣称复核者独立于实现。

review.json 以输出哈希绑定复核并明确 AI 辅助身份；用户亲自确认是独立状态，AI 复核不能替代用户或评审最终判断。

## 缺陷与贡献边界

初次结构检查未发现 M01 来源归属错误，也未充分验证 F02 的指定故障。后续增加 Trace 检查与逐题语义标准。引用校验仅核对原文出处和文本匹配，答案是否获得证据支持仍需语义复核。

尚需本人填写：实际亲自修改的文件、对方案取舍的理解、完整亲自复现和验收结果。未取得这些记录前保持未确认，不由 AI 代写个人经历。

## 时间与材料真实性

当前没有完整连续的人工投入计时，不能回溯编造各阶段耗时或声称恰好三小时完成。elapsed_seconds 仅代表对应运行耗时；XML 时间戳仅代表测试执行时刻，均不等于个人开发工时。安装、接口等待、额度中断和查收暂停应与主动开发时间区分。

原始输出、失败报告和修复后的运行分开保存。测试集参与修复、未执行的浏览器检查及其他限制在 [评估报告](03-evaluation.md) 中披露。真实密钥、.env、虚拟环境与原始资料压缩包不纳入提交。
