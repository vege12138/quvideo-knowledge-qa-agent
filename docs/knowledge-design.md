# 企业知识库设计说明

## 1. 业务背景

**星映科技（虚构）** 提供短视频制作、AI 视频生成、团队协作与企业 API 服务。员工和企业客户的支持人员经常需要查询财务、人事和产品规则。知识文件存在同时生效、口径不一致或适用套餐不同的情况。

目标：Agent 根据用户问题自主检索、读取原文、必要时补充检索，最终输出准确答案、文档 ID / 原文片段引用、资料缺口及任务状态。不允许不检索而编造。

## 2. 八份文档清单

| ID | 标题 | 知识范围 | 关键规则 |
|---|---|---|---|
| D01 | 员工费用报销管理制度 | 全体正式员工 | 30 自然日报销提交期限 |
| D02 | 费用报销操作补充通知 | 全体正式员工 | 15 自然日报销提交期限 |
| D03 | 团队标准版产品与协作规则 | 仅标准版工作区 | 活跃成员最多 5 人；最高 1080p |
| D04 | 团队专业版产品与协作规则 | 仅专业版工作区 | 活跃成员最多 50 人；最高 4K |
| D05 | AI视频生成积分与扣费规则 | 标准版+专业版 | 预扣 20 积分；失败后 60 分钟内返还 |
| D06 | AI视频生成失败排障FAQ | 标准版+专业版 | 故障排查；失败满 24 小时后才返还 |
| D07 | 企业API接入与权限申请指南 | 已签约企业 API 服务的客户 | 企业管理员申请；2 工作日审批 |
| D08 | 员工请假与审批制度 | 全体正式员工 | 年假提前 2 工作日；病假返岗后补交 |

## 3. 人工设计的文档关系

- **冲突对 R01：D01 ↔ D02**：相同适用人群、相同费用类型，30 vs 15 自然日。尽管 D02 版本日期较晚，但无明确废止或优先级文件，因此应列出两个候选规则并请求确认，不可直接选 15 天。
- **冲突对 R02：D05 ↔ D06**：相同套餐的 AI 生成失败返还规则；60 分钟内 vs 满 24 小时后，无法同时满足。
- **范围不同 R03：D03 ↔ D04**：标准版 5 人与专业版 50 人，不是冲突。问题未提供套餐时应澄清，提供套餐时只回答对应文档。
- **场景不同 R04：D08 年假与病假**：提前申请和返岗后补交适用于不同假别，不应判为冲突。

## 4. 分块与引用规则

每份文档 4 个有明确主题的段落；`doc_id` 和 `chunk_id` 在当前版本中固定。Markdown 文件是可读原文，`data/documents.json` 是供运行的等价结构化副本。

Agent 可以先调用 `search_documents(query, top_k)` 返回候选文档和片段，再调用 `read_document(doc_id)` 读取原文；最终引用必须至少包含 `doc_id`、`chunk_id`、`quote`。引用 `quote` 必须是该片段原文子串。引用真实存在不等于支持结论，仍需检查语义蕴含。

## 5. 测试策略

- 开发集 12 题，保留测试集 12 题；六类场景各有 2 道开发题和 2 道测试题。
- 工具失败通过注入参数在测试运行时模拟，可重复、可定位；`failure_injection` **不应该作为模型输入**。
- `mutation_cases.json` 应在独立知识库副本上执行，每次重建索引、清空会话缓存；确保答案随真实资料变化。
- `expected_facts` 是需要表达的语义事实，并非要求完全照抄；`must_not` 中的字符串说明常见错误结论，人工验收优先于仅按词匹配。
- 不提供现成的知识库冲突标签给 Agent；冲突必须由其检索读取文档后识别。

## 6. 说明

本数据是小规模合成验收集，用于展示流程和关键边界，不代表真实企业知识库分布。若只用 24 题进行提示词调优与展示，会存在评估过拟合风险；正式报告应如实说明这一限制。
