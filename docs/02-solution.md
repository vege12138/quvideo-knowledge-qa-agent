# 方案设计

本项目面向员工查询合成企业制度与产品规则。CLI、连续对话和本地网页共用 QAService；核心质量目标是让回答有可核查的证据，在资料冲突、资料不足和执行失败时诚实结束。需求及收尾规则见 [规格 v1.4](01-requirements.md)。

## 数据与检索选择

运行时只读取 data/documents.json：8 份文档、32 个片段，保留文档 ID、片段 ID、版本日期、适用范围及原文。data/docs/ 的 Markdown 供核查，evaluation/ 的题目、参考答案和 document_relations.json 只供离线评估，不作为运行知识或模型上下文。

字符 2—4 gram TF-IDF 的索引文本包含标题、适用范围、章节和正文。它无需额外 embedding 服务，适合当前小规模中文资料，易于复现和定位召回问题。检索先取各文档最佳候选，再补其余片段，避免同一文档占满结果；相关分数低于 0.025 的片段不返回。这个阈值是当前实现参数，不表示概率或事实可信度。

局限是跨词汇、强语义改写的召回可能不稳定。模型可以改写查询继续检索；是否引入向量或混合检索，应由新资料和失败案例证明收益，本轮不增加基础设施。

## 两个业务工具

| 工具 | 输入 | 输出及边界 |
|---|---|---|
| search_documents | query、top_k | 文档/片段 ID、标题、范围、日期、得分和短摘要；摘要不能直接成为最终证据 |
| read_document | doc_id、可选 chunk_ids | 文档元信息与逐字原文；不传片段时读整份文档 |

工具使用统一的成功/错误观察结果。合法的空搜索结果、无效参数、工具超时和执行异常有不同含义，不能统一解释为“知识库没有资料”。故障注入只由测试侧包装器读取，模型只看到实际工具错误，不接收题目分类、预期答案或恢复目标。

## 模型驱动循环

LangGraph 管理 model 和 tools 节点、状态及结束条件。每轮从问题和可选历史开始：

1. 模型决定搜索词、阅读对象或结束。
2. 工具节点校验参数、执行调用并写入观察结果。
3. 模型根据实际观察决定继续读取、改写搜索、追问或提交答案。
4. 最终 JSON 和引用校验不通过时，错误反馈给模型修正，仍计入同一执行预算。

固定代码负责路由、预算和校验；不按题号、文档 ID 或预置冲突配对返回业务答案。LangGraph 的价值是让循环状态和边界可检查，框架名称本身不证明 Agent 效果。真实动作变化须在运行 Trace 中核查。

DeepSeek 适配器通过 httpx 调用配置的 chat/completions 接口，允许模型选择工具。模型名、endpoint 和密钥来自环境变量或 .env。依赖的实际固定版本见 requirements.txt；pyproject.toml 声明兼容范围。Mock 演示搜索、读取和错误流程，不产出业务答案，也不作为真实模型决策证据。

## 证据、冲突与澄清

最终引用必须满足 doc_id/chunk_id 对应、本轮确实 read_document 读取、quote 是该原文的精确子串。系统提示要求保留每条规定的真实来源和范围；不能把一份文件的规定归到另一份，也不能因“日期较新”或“更严格”自行裁决。

clarification_reason 区分：

- conflict：至少两个不同 doc/chunk 对的有效引用，可来自同一文档；模型说明无法调和的规则并请求权威确认。
- missing_context：缺少套餐、场景或指代信息时追问，允许零引用，但 gaps 必须明确需要补充什么。
- 非澄清状态：reason 为 null。旧 JSON 可依默认值解析，新回答仍须满足校验。

引用子串与数量校验只能证明引用形式合法，不能证明结论受到支持或两段文字构成冲突。逐题语义复核专门检查事实、来源归属、范围和引用支持，见 [评估方法](03-evaluation.md)。

v1.3 进一步限定回答与状态只针对当前所问属性：同一主题下其他事项的冲突，不应扩展到最终回答或改变本来证据一致的结论。模型可以继续阅读核对；只有当前所问事项无法调和时才按 conflict 澄清。

v1.4 区分原文的直接声明与阅读后的缺失观察：资料未提供优先级时只能表述为“所读资料未提供”，不能伪称原文明示没有优先级。元信息不当作引用片段的原话；操作、位置、对象之间的关系也须逐项有原文支持，不能将分散事实拼成未记载的界面操作，避免无必要的附加建议。

## 预算与失败边界

默认限制为 8 次模型调用、12 次工具调用、单次模型请求 45 秒、整次运行 180 秒，可通过配置调整。每个工具分别计数；修正、重试与补查不另开预算。

search 的所有查询共用失败键；read 按 doc_id 使用失败键。timeout 与 tool_exception 累计，同键成功清零，其他键成功及切换 query/chunk 不清零。invalid_request 不计连续故障，但仍消耗工具总预算。第三次连续失败先记录 Trace 与次数，再返回 tool_error / tool_failure_limit，并跳过当前批次余下调用。此前模型自行决定是否重试、换查或停止。总预算、时间和故障边界按先达到的条件结束。

tool_error 表示工具或模型服务失败；incomplete 表示预算或总运行时间耗尽。模型主动报告证据暂不可读可以提前返回 tool_error；不必为了达到第三次而强制继续请求。

## 统一服务与界面

核心接口为 await service.ask(question, history=None)，返回 QAResult：answer、status、clarification_reason、citations、gaps、run_id、reason_code、trace、metrics、mode。历史仅帮助理解指代，不能替代本轮证据。每次请求创建独立工具状态，避免引用与故障计数跨轮共享。

CLI 用 argparse 提供 ask、chat、JSON 输出、Trace 保存和显式 Mock。网页用 FastAPI 托管静态页面，POST /api/chat 接收 question 与可选 session_id，返回统一结果及 session_id；DELETE /api/sessions/{session_id} 删除会话。凭证只在服务端使用。

网页会话只存内存，最多保留 100 个会话，忙碌会话不能被同时提交或删除；单会话最多 20 轮。服务重启会丢失历史。当前接口为完整响应，无流式输出、账号、权限管理或多进程会话共享，因此仅定位为本地演示。

## Trace 与验证边界

Trace 记录模型动作、工具参数与观察、校验失败、结束状态和调用/耗时指标，不收集或要求模型内部思维链。保存前进行密钥清理；模型 HTTP 错误不保存响应头或原始服务响应体。

当前真实知识是合成资料。评估结果只支持所列案例上的结论，不能外推为任意企业知识或生产环境可靠性。网页接口测试与浏览器视觉检查分别记录，前者不能代替后者。
