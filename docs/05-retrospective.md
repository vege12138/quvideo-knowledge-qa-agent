# 项目复盘

这份复盘根据实现和执行证据总结工程问题，不代替候选人个人心得。个人学习经历、亲自修改和实际投入时间仍需本人补充，见 [AI 使用记录](04-ai-usage.md)。

## 已观察到的问题

| 观察 | 原因与影响 | 本轮处理 |
|---|---|---|
| 一次正常 CLI 答对不足以证明题目完成 | 没有覆盖冲突、资料外、改写、追问与故障 | 保留 MVP，按六类问题和四次变更补证据 |
| 结构通过仍可能答错 | 引用 ID/子串合法不代表来源归属和结论正确；M01 暴露问题 | 结构与 AI 辅助语义复核分别统计，逐题写依据 |
| 正确数字旁边仍可能有无依据表述 | 收尾 r2/H03 把未提供优先级称为原文明示；K04 把分散事实拼成界面操作 | v1.4 规范直接声明、缺失观察和操作关系；保留失败并重跑，不掩盖为结构全过 |
| 故障标签不等于真的注入故障 | 初次包装器漏掉异常模式/指定文档，F02 的通过无法证明恢复 | 严格校验注入配置，核查实际工具事件 |
| 只在提示中要求停止不够 | 模型可能换词或换片段继续失败，原总预算不限制同一故障 | 设置第三次失败硬边界，保留此前模型决策 |
| 澄清也需要验收结构 | 冲突与缺少用户上下文的证据要求不同 | clarification_reason 分类校验，再做语义复核 |
| 功能先于验收文档推进 | CLI 后已有网页，但阶段文档仍“实现中”、必需文档缺失 | 本轮先补规格和阶段计划，再记录结果与未完成项 |
| 保留测试用于修复 | 原测试集已不独立，继续报保留成绩会误导 | 保存首次结果，后续标为回归 |

## 方案取舍

32 个片段采用字符 TF-IDF 能减少服务依赖，检索较易解释；代价是跨表达召回有限。当前先验证事实来源、冲突和失败边界，有新失败证据后再决定是否增加语义检索。

CLI 和 FastAPI 共用核心服务，业务规则集中验证。网页改善演示，但不能代替模型动态动作与原文证据。当前本地、完整响应、内存会话用于演示，本轮不增加账号、上传、向量库或远程部署。

## SDD 执行改进

后续改动先写需求增量、输入输出和验收例，再实现，将测试输出与需求编号绑定。已有历史不追溯补成理想流程：旧文档滞后、首次测试缺陷和未执行项都保留说明。

重跑生成新目录，复核绑定 run_id 和输出哈希。源码、数据或输出变化后重新验证受影响范围，不复制旧报告冒充新结果。
