# 项目复盘

依据实际实现、失败输出与修复过程整理。候选人参与了选题、需求与阶段决策、CLI运行和GitHub发布；实现、完整评估与本轮文档整理由AI辅助完成，贡献和时间见 [AI使用记录](04-ai-usage.md)。以下为项目过程中形成的技术总结，不虚构候选人独立完成全部代码或已掌握全部模块。

## 问题、处理与认识

| 实际问题 | 处理与形成的认识 |
|---|---|
| 一次CLI答对只能覆盖单个路径 | 按明确答案、冲突、资料外、改写、追问、工具失败六类验收；正常路径不代表全部完成 |
| 引用ID与原文子串正确，正文仍可能没有依据 | 将结构检查和语义支持分开统计，逐题绑定输出复核 |
| C03只问预扣金额，却扩展退款冲突并追问 | 限定当前属性，加入answered/gaps硬校验与通用正反示例；只靠格式校验无法防止错误选择conflict |
| K02附加超期处理却漏引原文 | 检查保留的每条业务规定，包括附注；不只核主数字 |
| 故障标签未必真正触发指定异常 | 校验注入参数和真实Trace，恢复必须看到失败后实际成功 |
| 模型改查询或换片段可能绕过重试计数 | 搜索统一计数、读取按doc_id计数，第三次失败硬停止，重试与修正计入总预算 |
| 测试集参与修复后不再独立 | 披露为回归评估，保留旧失败，不把结果称为独立准确率100% |
| 只有本地运行还不等于完成交付 | 准备可复制命令、版本和证据索引；候选人上传后以匿名访问核验评审入口 |

## 技术取舍

32片段的小型中文知识库先用字符TF-IDF，可本地运行且便于解释；不直接增加向量库和服务依赖。对陌生表达的召回仍需新数据验证，出现实证后再决定是否增加语义检索或排序。

LangGraph提供循环与状态管理，模型仍决定查询、阅读、补查和停止。框架名称不证明Agent能力；F02中首次整份文档读取失败、后续改读片段成功的真实记录才展示动态动作。

CLI与FastAPI复用同一服务，使业务规则集中。网页用于本地交互展示；实际Edge检查补齐等待、防重复、引用、新会话和错误恢复，不能据此宣称生产可用。
